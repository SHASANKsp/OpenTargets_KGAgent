The spine the applications traverse

Node labels and directions are inferred from the relationship names — the genetics core runs variant → credible set → study → disease, with locus-to-gene and consequence edges landing on targets, and the drug/clinical layer hanging off targets and diseases.

Confirm the real labels and directions before building on any query below — CALL db.schema.visualization() renders the actual model, and CALL db.schema.relTypeProperties() lists the properties (and types) on each relationship.

01 · Genetic target discovery

Disease → causal genes

Disease←STUDIESStudy←FROM_STUDYCredibleSet→L2GTarget

The core Open Targets workflow: fine-mapped GWAS signals resolved to their most likely gene. This is your primary genetically-supported target list per indication.

core Cypher
Query
MATCH (d:Disease {id:$efo})<-[:STUDIES]-(s:Study)
      <-[:FROM_STUDY]-(cs:CredibleSet)-[l:L2G]->(t:Target)
WHERE l.score >= 0.5
RETURN t.approvedSymbol, max(l.score) AS l2g,
       count(DISTINCT s) AS studies
ORDER BY l2g DESC

Variant-to-gene assignment

Variant→IN_CREDIBLE_SETCredibleSet→L2GTarget

Given a lead or candidate variant, rank the genes it most plausibly acts through — the read-out a variant-interpretation tool sits on top of.

core Cypher
Query
MATCH (v:Variant {id:$vid})-[:IN_CREDIBLE_SET]->
      (:CredibleSet)-[l:L2G]->(t:Target)
RETURN t.approvedSymbol, l.score
ORDER BY l.score DESC

Coding-variant target evidence

Variant→ASSOCIATED_WITHDisease · Variant→MOST_SEVERE_CONSEQUENCETarget

Targets where a disease-associated variant has direct HIGH/MODERATE protein impact — the strongest, most interpretable class of genetic evidence.

needs: consequence impact field
Query
MATCH (v:Variant)-[:ASSOCIATED_WITH]->(d:Disease {id:$efo})
MATCH (v)-[c:MOST_SEVERE_CONSEQUENCE]->(t:Target)
WHERE c.impact IN ['HIGH','MODERATE']
RETURN t.approvedSymbol, collect(DISTINCT c.label) AS csq,
       count(DISTINCT v) AS variants
ORDER BY variants DESC

Pleiotropy scan

Target←L2GCredibleSet→…→Disease ×N

Targets genetically linked to many distinct diseases. Reads two ways: a repurposing / master-regulator hub, or an on-target safety flag for broad phenotypic consequence.

Query
MATCH (t:Target)<-[l:L2G]-(:CredibleSet)
      -[:FROM_STUDY]->(:Study)-[:STUDIES]->(d:Disease)
WHERE l.score >= 0.5
WITH t, count(DISTINCT d) AS diseases
WHERE diseases >= 5
RETURN t.approvedSymbol, diseases ORDER BY diseases DESC
02 · Target validation & prioritisation

Composite multi-evidence score

Target · L2G + EXPRESSED_IN + PARTICIPATES_IN + HAS_MODEL_PHENOTYPE + INTERACTS_WITH

Aggregate genetic, expression, pathway, model-organism and network evidence per target–disease pair into one tunable score — the backbone of a prioritisation dashboard.

weighting is yours to set
Query sketch
MATCH (t:Target {id:$ens})
OPTIONAL MATCH (t)<-[l:L2G]-(:CredibleSet)-[:FROM_STUDY]->
              (:Study)-[:STUDIES]->(:Disease {id:$efo})
OPTIONAL MATCH (t)-[e:EXPRESSED_IN]->(:Tissue {id:$tissue})
OPTIONAL MATCH (t)-[:HAS_MODEL_PHENOTYPE]->(mp)
RETURN t.approvedSymbol,
       max(l.score) AS genetic,
       max(e.rna)   AS expression,
       count(DISTINCT mp) AS model_phenos

Tissue-selective target filter

Target→EXPRESSED_INTissue

Keep targets expressed in the disease-relevant tissue and low elsewhere — the expression-selectivity screen that defines a therapeutic window.

needs: expression level field
Query
MATCH (t:Target {id:$ens})-[e:EXPRESSED_IN]->(tis:Tissue)
RETURN tis.name, e.rna, e.protein
ORDER BY e.rna DESC

Mouse–human phenotype concordance

Target→HAS_MODEL_PHENOTYPEMousePhenotype ↔ Disease→HAS_PHENOTYPE

Does perturbing the target in mouse recapitulate the human disease phenotype? Strong orthogonal validation, bridged through the phenotype ontology.

needs: HPO↔MP mapping

PPI neighbourhood & backups

Target↔INTERACTS_WITHTarget

Expand a validated target to its high-confidence interaction partners — backup targets in the same complex or pathway when the primary is undruggable.

Query
MATCH (t:Target {id:$ens})-[r:INTERACTS_WITH]-(n:Target)
WHERE r.score >= 0.5
RETURN n.approvedSymbol, r.score, r.source
ORDER BY r.score DESC
03 · Safety & de-risking

Target adverse-event profile

Drug→TARGETSTarget · Drug→HAS_ADVERSE_EVENTEvent

Aggregate the adverse events reported across every drug that hits a target — an empirical, on-target safety signature before you commit to it.

Query
MATCH (dr:Drug)-[:TARGETS|CLINICALLY_TARGETS]->(t:Target {id:$ens})
MATCH (dr)-[:HAS_ADVERSE_EVENT]->(ae)
RETURN ae.name, count(DISTINCT dr) AS drugs
ORDER BY drugs DESC

Broad-expression toxicity risk

Target→EXPRESSED_INTissue ×N

Count the tissues where a target is meaningfully expressed — ubiquitous expression is a first-order flag for on-target off-tissue toxicity.

needs: expression level field
Query
MATCH (t:Target {id:$ens})-[e:EXPRESSED_IN]->(tis:Tissue)
WHERE e.rna >= $cutoff
RETURN count(DISTINCT tis) AS tissues_expressed

Pharmacogenomics & warnings

Drug→HAS_PGX · HAS_WARNING

Surface pharmacogenomic liabilities and black-box warnings attached to drugs against a target — known clinical safety baggage for the mechanism.

Query
MATCH (dr:Drug)-[:TARGETS]->(t:Target {id:$ens})
OPTIONAL MATCH (dr)-[:HAS_PGX]->(p)
OPTIONAL MATCH (dr)-[:HAS_WARNING]->(w)
RETURN dr.name, collect(DISTINCT p.label) AS pgx,
       collect(DISTINCT w.description) AS warnings

04 · Repurposing & indication expansion

Genetically-supported repurposing

Drug→TARGETSTarget←L2G…→Disease′

A drug whose target is genetically linked to a disease it is not yet indicated for — the highest-value repurposing signal in the graph, with a whitespace filter built in.

core Cypher
Query
MATCH (dr:Drug)-[:TARGETS]->(t:Target)<-[l:L2G]-(:CredibleSet)
      -[:FROM_STUDY]->(:Study)-[:STUDIES]->(d2:Disease)
WHERE l.score >= 0.5 AND NOT (dr)-[:INDICATED_FOR]->(d2)
RETURN dr.name, t.approvedSymbol, d2.name, l.score
ORDER BY l.score DESC

Indication landscape & whitespace

Drug→INDICATED_FOR / INVESTIGATES / TESTED_INDisease

Map where a drug or mechanism is already approved versus merely in trials versus untouched — the competitive whitespace view for a target class.

Query
MATCH (dr:Drug)-[:TARGETS]->(:Target {id:$ens})
OPTIONAL MATCH (dr)-[:INDICATED_FOR]->(app:Disease)
OPTIONAL MATCH (dr)-[:INVESTIGATES|TESTED_IN]->(trial)
RETURN dr.name, collect(DISTINCT app.name) AS approved,
       count(DISTINCT trial) AS trials

Clinical-precedence scoring

Target←CLINICALLY_TARGETS / TESTED_INDrug

Rank targets by depth of existing clinical validation — how far any drug hitting them has advanced. De-risks a novel programme by precedent.

Mechanism-shared repurposing

Drug·Target→PARTICIPATES_INPathway←disease targets

Find drugs whose target shares a pathway with a disease's genetic targets, even without a direct target hit — pathway-level repurposing hypotheses.

needs: pathway coverage
05 · Variant interpretation & functional genomics

Fine-mapped locus browser

Study→HAS_LEAD_VARIANTVariant→IN_CREDIBLE_SETCredibleSet

Reconstruct any study's fine-mapped credible sets and their member variants — the data behind a locus-zoom / signal-explorer interface.

Query
MATCH (s:Study {id:$study})-[:HAS_LEAD_VARIANT]->(lead:Variant)
MATCH (cs:CredibleSet)-[:FROM_STUDY]->(s)
MATCH (v:Variant)-[m:IN_CREDIBLE_SET]->(cs)
RETURN lead.id, v.id, m.posteriorProbability
ORDER BY m.posteriorProbability DESC

Molecular QTL linkage

Study→MEASURESMolecularTrait

Connect QTL studies to the molecular trait they measure (e.g. an eQTL for a gene), linking regulatory variants to their target through the study layer.

confirm MEASURES semantics

Variant functional dossier

Variant→ASSOCIATED_WITH · MOST_SEVERE_CONSEQUENCE · IN_CREDIBLE_SET

One call assembling everything the graph knows about a variant — its traits, coding consequence, gene assignment and fine-mapping context.

Query
MATCH (v:Variant {id:$vid})
OPTIONAL MATCH (v)-[:ASSOCIATED_WITH]->(d:Disease)
OPTIONAL MATCH (v)-[c:MOST_SEVERE_CONSEQUENCE]->(t:Target)
RETURN collect(DISTINCT d.name) AS traits,
       collect(DISTINCT [t.approvedSymbol, c.impact]) AS consequence
06 · Disease & phenotype analytics

Disease–disease similarity

Disease→HAS_PHENOTYPE / shared targets←Disease

Cluster diseases by shared phenotypes or shared genetic targets — surfaces mechanistic overlap, comorbidity and repurposing adjacencies.

Query
MATCH (d1:Disease)-[:HAS_PHENOTYPE]->(p)<-[:HAS_PHENOTYPE]-(d2:Disease)
WHERE id(d1) < id(d2)
RETURN d1.name, d2.name, count(p) AS shared
ORDER BY shared DESC LIMIT 100

Ontology roll-up & expansion

Disease→SUBCLASS_OF / IS_A / HAS_PARENTDisease

Propagate evidence up and down the disease hierarchy — aggregate child-disease associations to a parent term. This is the backbone your semantic-search layer already leans on.

core Cypher
Query
MATCH (child:Disease)-[:SUBCLASS_OF*1..4]->(d:Disease {id:$efo})
MATCH (v:Variant)-[:ASSOCIATED_WITH]->(child)
RETURN d.name, count(DISTINCT v) AS rolled_up_variants

Phenotype-driven target search

Phenotype←HAS_MODEL_PHENOTYPETarget

Start from a phenotype of interest and find the targets whose perturbation produces it — a reverse-genetics entry point into target discovery.

Query
MATCH (t:Target)-[:HAS_MODEL_PHENOTYPE]->(mp {id:$mp})
RETURN t.approvedSymbol, count(*) AS evidence
ORDER BY evidence DESC
07 · Pathway & network biology

Pathway enrichment of targets

Target→PARTICIPATES_INPathway

Test whether a disease's genetic targets concentrate in a pathway — points to pathway-level intervention rather than a single node.

Query (observed counts)
MATCH (t:Target)-[:PARTICIPATES_IN]->(pw:Pathway)
WHERE t.id IN $diseaseTargets
RETURN pw.name, count(*) AS hits
ORDER BY hits DESC  // feed hits + pathway size to a hypergeometric test

PPI module detection

Target↔INTERACTS_WITHTarget · community detection

Run Louvain / Leiden over the interaction graph to find functional modules — target complexes worth hitting together.

GDS — check licence
Query

YIELD nodeId, communityId RETURN communityId, count(*) ORDER BY count(*) DESC

Notes & caveats

Schema is inferred. Node labels, directions and property names above are read from the relationship names — verify each against db.schema.visualization() and db.schema.relTypeProperties() before building. Pills marked needs: flag an application that depends on a node/edge property (expression level, subcellular localisation, effect direction, MP↔HPO mapping) that may not be loaded.

Licensing. Most core Neo4j GDS algorithms (Louvain, PageRank, FastRP) ship in the free GDS library, but some algorithms, Bloom, and Neo4j Enterprise features are commercially licensed; PyKEEN is MIT but individual pretrained models and some GNN stacks are not. Confirm the licence of any network-analytics or embedding component before it goes into a product.

Filtering trade-off. Everything here runs on the post-QC graph, where genetic edges were thresholded for confidence. Applications that need recall at the margins — fine-mapping tails, allelic series, novel-signal discovery — should run against a fuller build, not this working instance.
